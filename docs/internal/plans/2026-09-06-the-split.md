# The split - exlib, exmods and the workspace

> **For agentic workers:** the driver (the main session) executes Tasks 1, 2 and 6 itself: history
> surgery, remotes and memory stores are not builder work. Tasks 3, 4 and 5 take a fresh `builder`
> each, one at a time, each in the repository it names. No review pass. Every gate is run in both
> repositories before the task is called done.

**Status** written 2026-09-07, not started. Step 5 of
[2026-09-06-repo-restructure.md](2026-09-06-repo-restructure.md): rulings L1-L5, L7, R1, P8 and
the memory-store trap. Runs after the extools plan (step 4), so by then the CLI, the packaging build
and the verify tool are consumed through the wrapper and nothing under `scripts/exmod/` or
`infra/CakeBuild` or `infra/tools/ExlibVerify*` remains in this repository.

**Goal:** three repositories under one private workspace. `exlib` is the framework: the mod, its
modules, the harness, the generators, the samples, the templates, the wiki and the framework
design pages. `exmods` is the family: iiex, siex, the workbench, the family design pages, the
maintenance branch and the old tags. The workspace holds the plans, the worklog, the research, the
shared installs, and the switch that makes the family build against exlib's source when both are
checked out side by side.

**Architecture:** exlib's history is extracted with `git filter-repo` on a fresh clone and the
result becomes the exlib repository at today's `mods/exlib` folder layout, flattened to the root;
this repository, renamed, drops those paths and becomes exmods. The family's csprojs reference exlib
by project when `ExlibRoot` is set and by package when it is not; the workspace's
`Directory.Build.props` sets it. Memory stores are split by subject and pruned.

**Tech stack:** git filter-repo, MSBuild, NuGet, GitHub (`gh`, repositories created private), the
Pi's bare repositories.

## Traps that apply to every task

- `git filter-repo` runs on a fresh `git clone --no-local` under `/tmp`, never in a working
  checkout. It refuses a clone with a remote; that is what a fresh clone gives you.
- Carry `.gitattributes` (the EOL rule that ended the CRLF flip), `.editorconfig`, `.csharpierrc`,
  `Directory.Build.rsp` (node reuse off) and `global.json` into every repository.
- The trusted-publishing policy on nuget.org names a repository and a workflow file; it is created
  for `ringavirda/exlib` and `release.yml` in step 6, not here.
- `RepositoryUrl`, the wiki's page links, the README's links, the sample template's comments and
  the CI files all name `modding-vsexpanded`; each repository gets a sweep and the gate greps for
  the old name.
- The exlib repository's own memory store does not exist until Task 6 creates it; a session rooted
  there before that loads nothing.
- Every gate runs in source mode (both repositories checked out, `ExlibRoot` set by the workspace)
  and, for exmods, once more in package mode with `-p:ExlibRoot=`; the package-mode run needs the
  published prerelease from step 6 and is red until then. That is expected and is said in the
  Progress line, not hidden.
- Never `git stash`, `git reset` or `git checkout --` in a working checkout.

The 8 citations from the industry module to `gas-system.md`, `material-roles.md`,
`machining-line.md`, `heat-balance.md` and `materials.md` (family pages that stay in exmods) become
prose or a wiki link in the same sweep; the 50 distinct citations from iiex and siex are unaffected.

exlib keeps today's folder names inside the mod rather than moving to `src/<Package>/`: the
per-mod convention (`src/` is the mod's own project, its satellite packages are sibling folders,
one per shipped package, so a fifth module is a fifth folder) holds at the repository root exactly
as it held under `mods/exlib/`, `RepoManifest`'s conventions resolve it without overrides, and no
relative path inside the moved tree changes.

### exlib's root files

`Directory.Build.props` at exlib's root is today's `mods/Directory.Build.props` with the import of
`build/ExpandedLib.props` re-pointed (`$(MSBuildThisFileDirectory)build/`); `Directory.Build.targets`
the same for the targets. Today's `mods/exlib/Directory.Build.props` (pack metadata) becomes
`src/Directory.Build.props`, importing the file above it as it does now. `Directory.Packages.props`
keeps every row (the `ExpandedLib*` rows still read `src/modinfo.json`). `exmod.json`: mods
`{"exlib": {"path": "."}}`, the two samples, series 1.22/1.21/1.20, packages `src`, `industry`,
`testing`, tools pinned. The solution is new, `ExpandedLib.sln`, made with `dotnet new sln` and
`dotnet sln add` over the nine projects the filter used to list. The wiki's `_Sidebar`, `Home` and
`Getting-Started` links, the README links and `RepositoryUrl` name `ringavirda/exlib`.

### exmods' root files

`mods/Directory.Build.props` keeps the manifest defaults and the test settings and sets `ExlibRoot`
only from the workspace (it no longer has a sibling `exlib/` to default to); it imports
`$(ExlibRoot)build/ExpandedLib.props` when `ExlibRoot` is set and nothing otherwise, since in
package mode the package's own `build/` files arrive through NuGet. `mods/Directory.Build.targets`
the same for the targets. `Directory.Packages.props` carries the test packages and literal
`ExpandedLib`, `ExpandedLib.Industry`, `ExpandedLib.Testing` rows at the version step 6 publishes
(`0.8.0-preview.1`), which a release of exlib bumps by hand. iiex and siex (mods and tests)
reference exlib, industry, the harness and the generators exactly the way the samples do after
step 2 (the two conditioned item groups). A guard in each mod's suite asserts that its
`modinfo.json` exlib dependency floor equals the `ExpandedLib` row (P8). `exmod.json`: mods iiex and
siex (with iiex's `game` overlay), no samples, no extra tests, no packages, `depends.exlib.github`
`ringavirda/exlib`, series 1.22/1.21/1.20, tools pinned. `VintageStory.sln` loses the exlib and
sample projects. CI: `tests.yml` runs the current lane in package mode; `tests-legacy.yml` is
removed (legacy is a workspace, source-mode activity); `release.yml` packs the mod zips and creates
the GitHub release, with no NuGet steps; `wiki-sync.yml` goes with the wiki. `infra/test/coverage-floors.json`
keeps iiex and siex. The GitHub repository keeps its name; the local folder is `exmods` unless the
owner names it otherwise.

### Memory stores

The 226 notes under `~/.claude/projects/-home-fallen-src-modding-vsexpanded/memory/` are split by
the classification table produced for this plan (kept in `docs/research/2026-09-07-memory-split.md`
in the workspace once it exists): EXLIB notes to the exlib store, EXMODS to the exmods store,
PARENT to the workspace store, ALL copied into every store, DROP deleted. Each store gets a
rebuilt `MEMORY.md` in the same grouped form. Absolute paths inside notes that name
`/home/fallen/src/modding-vsexpanded` are rewritten to the note's own new root by a sweep; the
old store directory is renamed with a `.retired` suffix rather than deleted, and removed after the
owner has worked from every new root at least once. `~/.claude/CLAUDE.md`'s cross-project table
lists the three new stores and drops the old row.
